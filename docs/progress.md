## 验收证据

- 在新的临时目录执行 `npm ci`，依赖安装成功。执行 `npm run build` 完成全工程类型检查、Host 编译与 Vite 生产构建。执行 `npm audit` 时未报告已知漏洞。
- 实际启动 `npm run dev`、`npm start`。Vite 开发代理可以提交请求；生产地址的页面返回 HTTP 200，状态接口报告版本 0.1.0。
- `npm test` 的 13 项测试覆盖身份与会话隔离、设置持久化、Origin/Host 来源检查、部分文本、取消、协议错误、Adapter 进程异常退出、重复审批。独立测试子进程运行 Host，强制终止后重启，确认 SQLite 将遗留任务、工具与部分消息正确标记为中断。竞争 Host 无法取得同一数据库。
- `npm run test:live` 通过。使用显式进程代理连接真实模型，查询提示中未包含随机文件内容。在关闭 SSE 后，由 Host 持续处理；人工核对并单次批准读取隔离目录文件的原生请求后，模型正确报告内容。重启 Host 后沿用原线程复述结果，随后一轮取消成功。
- 最终提交使用本机可用的 `gpt-6.2-sol` 和显式代理复测上述三轮。在 Chrome 核对并批准单次文件读取后，真实工具、断线续跑、重启恢复及取消全部通过。
- 使用 Playwright 驱动系统 Chrome，从空库创建身份、修改执行超时并刷新核对、检测 Codex、发消息、执行中关闭页面并重开。回复带有测试人格配置的前缀。390px 视口下三个页面均无横向溢出，浏览器未报告页面运行错误。开发模式另验证了 SSE 与写入。浏览器实测使用机器临时目录中的一次性脚本，仓库内保留 Host 和 Runtime 的可重复验收脚本。

## 已知限制

- 模型可达性依赖当前终端网络与 Codex 原生账户。一次直连尝试出现超时。Windows 沙箱启动 PowerShell 失败时，模型可能请求额外审批，本机验收中出现过这一情况。
- V0.1 每个 Turn 启动一个 App Server，再用原生线程 ID 恢复上下文，因此每次发送都有启动成本。原生线程丢失后，平台仍可展示本地聊天记录。长会话使用全量快照，当前没有分页。
- 测试覆盖当前 Windows PC 和所列 Codex 版本，其他系统、浏览器、Codex 版本以及长期高负载尚待验证。远程访问、第二种 Runtime、长期记忆和多 Agent 协作属于后续版本。
