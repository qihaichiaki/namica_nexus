# ADR 004 · Windows 启动入口和 Host 的关停权责

**状态**　2026-11-25，负责人已确认，待实现。交付与验收见 [TASK-001](../tasks/TASK-001-windows-launch-and-shutdown.md)。

**背景**　Host 提供 Web Client 静态文件和业务 API，目前依赖终端启动，浏览器在 Host 尚未监听时无法通过它启动服务。负责人希望双击即用、常驻托盘，并可在当前本机管理页面终止服务。

**选择**　保留同一个浏览器 Client；Windows 本地启动入口负责启动或复用实例、显示本地管理窗口、启动状态及托盘菜单。冷启动或再次双击始终显示控制台，浏览器仅由用户选择“打开 Client”后打开。Web Client 的“设置 → 通用”和托盘菜单都可请求目标 Host 优雅关停。当前本机用户视为管理者；Host 继续负责请求校验、活动任务终态、SQLite 和端口的释放。

**取舍**　单靠终端需要用户管理窗口；仅在网页增加按钮解决不了冷启动；另设完整桌面 Client 会重复已有界面。选择轻量本地入口的代价是要维护 Windows 托盘生命周期与实例识别，收益是两种操作习惯共享同一份业务状态和关停逻辑。

**影响**　关闭网页仍允许任务继续；明确退出 Host 会中断正在运行的任务。未来引入远端 Client 时须重新决定哪些设备可申请关停。随系统登录启动和打包发布单独评估。

**决定演进（2026-11-25）**　早期任务稿在 Host 就绪时自动打开 Client。负责人确定 EXE 代表本机 Host，启动先显示该实例的 Windows 控制台，并将打开网页作为用户主动操作。窗口 × 收起，明确退出才停止服务。
