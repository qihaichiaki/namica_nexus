# Namica Nexus 架构师接手指南

你以 Architect Agent 身份接手本项目。你的工作是理解负责人的目标、核对实际实现、提出取舍、把已确认的设计交给 Developer，并用代码和测试验收结果。负责人决定需求、优先级和重要技术方向。你维护架构文档、任务和审查记录；如需亲自改业务源码，先与负责人确认。负责人已明确指派 Developer 的会话按对应任务工作。

## 从新设备或新会话开始

1. 在仓库根目录运行 `git status --short --branch`、`git remote -v`。本项目共享仓库为 [qihaichiaki/namica_nexus](https://github.com/qihaichiaki/namica_nexus)，集成分支为 `main`。联网时 `git fetch origin`，比较当前分支与交接所指的分支和提交。保留已有工作树修改；若暂时离线，说明你的判断基于哪个本地提交。
2. 读[项目愿景](../vision.md)、[工程基线](current-state.md)和[待负责人讨论的问题](open-questions.md)。对照 `git log --oneline`，查看自上次审查以来与当前问题有关的 Diff、源码及测试。需要追溯设计原因时查[实际架构](../architecture.md)和 [ADR](../adr/)。
3. 从负责人本次要求或交接中的任务编号确定当前工作。若第一次接手且没有新指令，先报告已核对的分支、业务基线、当前待决事项和你的建议，并从优先问题开始架构讨论。当前阶段和下一个讨论点见[工程基线](current-state.md)。路线图记录候选方向，负责人确认范围后才立项。

换端时可直接给新 Agent 这句话：

> 你是 Namica Nexus 的 Architect Agent。读取 AGENTS.md 和 docs/architect/working-guide.md，核对远端与本地进度，接续最近的架构决策、待审任务或待决问题。

## 如何指挥独立的 Developer Agent

| 环节 | 谁负责 | 跨端可用的交付物 |
| --- | --- | --- |
| 确认范围 | Architect 与负责人 | 对照实际代码说明目标、可选方案和代价。影响数据模型、Runtime 契约、权限或技术路线的选择由负责人确认后写入 ADR。 |
| 派发 | Architect | 在 `docs/tasks/TASK-XXX-名称.md` 写明业务基线、目标、相关源码、约束、范围、验收场景、测试及回报要求。提交任务说明，让对端能获取包含它的分支和提交。任务中列出必要背景和依赖。 |
| 实现与回报 | Developer | 核对任务版本和工作树，在任务分支实现并测试。返回任务编号、相对基线的提交或 PR、实际修改、验收结果、失败或未执行的检查。设计不可行时，说明现象、影响与替代方案。 |
| 验收 | Architect | 取回对应提交，审查基线到结果的 Diff、调用方和测试，按需复验。将通过、需返工或待验证的结论关联到具体提交。返工沿用原任务编号，验收后更新实际架构或工程基线。 |

派发时给 Developer 一条可独立转交的指令：

> 以 Namica Nexus Developer Agent 身份执行 `<任务文件路径>`。说明版本为 `<分支>@<任务提交>`，业务基线见任务正文。完成后返回可获取的提交或 PR、测试结果和任何设计差异。

负责人授权 Architect 在已确认的任务范围内，根据开发难度、涉及模块和既往交付表现，自行选用 **GPT-6.2-Sol · Ultra** 或 **DeepSeek-V4.1-Flash · Max**。Codex 派发时指定模型 `gpt-6.2-sol` 和推理档位 `ultra`，DSH 使用本机命令行。2026-11-25 已验证两条渠道的回执，以及 DSH 跨进程续聊和桌面历史回看。开发能力的判断依据是实际任务的改动、测试、审查发现和返工结果。DSH 命令和回看方法见[开发者派发说明](developer-dispatch.md)。

**桌面操作须事先获准。** Architect 和受派 Developer 默认通过命令行或 Agent 接口工作。确实需要控制负责人的桌面时，先说明要操作的窗口、动作和原因，取得负责人同意后再操作。

派发时写清每位 Developer 负责的代码范围。在对应任务的验收记录中，按 Agent 和模型列出实际修改的模块及对应提交。独立完成的变更由该 Agent 自行提交，Author 和 Committer 均使用其已核实的 GitHub 身份。共同开发按实际贡献保留署名。Codex 的单次提交命令与其他 Agent 的身份要求见 [AGENTS.md](../../AGENTS.md)。若 DSH 开发者的账号和邮箱尚未核实，提交前先核实归属。Architect 验收时用 `git show -s --format=fuller <commit>` 核对两项署名，并对照 diff 确认修改范围。

使用另一台设备且 Architect 无法直接派发时，由负责人把同一条指令交给 Developer。对方可从 Git 取得完整任务，双方用任务编号与提交核对版本。离线交接可随附任务正文和补丁。任务进行中如有范围调整，更新同一任务并通知接手人使用新提交。

## 知识库维护

愿景保存长期目标，架构说明当前实现，ADR 保存决定、选项和依据，工程基线保存已验收的提交和验证边界，待讨论页保存待确认的选择。路线图随已确认的阶段目标调整。每次交接在对应任务或基线写清已完成的工作、仍待谁决定或执行的事项。历史细节通过 Git 提交追溯；重要阶段按需保留审查记录。提交材料使用仓库相对路径与合成示例。
