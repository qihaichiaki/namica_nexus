# 待负责人讨论

依据为[首次工程审查](current-state.md)，日期 2026-11-25。以下建议均待确认，当前没有已派发的 V0.2 任务。

## Q1 · 原生线程无法恢复时，Host 如何重建上下文？

**已定原则**　更换账号、模型或 Runtime 时，平台身份、人格、历史及未来的长期记忆保持原有归属。原生线程不可恢复时，未来考虑由 Host 用这些材料辅助重建。V0.1 可读取原始记录，也可为同一身份新建会话。[ADR 002](../adr/002-local-storage.md)

**待定细节**　何时提示重建、如何选择有来源的历史与记忆、向新 Runtime 提供哪些内容，以及怎样向用户展示原线程和新线程的关系。用一段有未完成操作的历史验收时，还应确认重建上下文不会重放已执行的工具操作或沿用旧审批。

## Q2 · 第二个 Runtime 如何选择，哪些能力必需？

**现象。** 当前仅有 Codex 生产实现。通用接口声明流式、恢复、取消和审批，Host 对每轮均安排超时取消。策略、配置和 UI 尚未按能力协商。仅靠布尔值难以区分“停止收到输出”和“外部执行已停止”。

**选项。** 可以要求第二个产品提供与 Codex 对等的能力，缩小可选范围；也可以以真实的能力差异验证平台，定义缺失时用户看见的行为及准入条件。ACP 等协议是候选接入途径；其适用性取决于选定产品和版本。

**建议。** 请负责人从最希望实际使用的候选（如 DSH 或 Claude Code）确定验证优先级。记录官方自动化入口、许可证、Windows 版本、认证、工具权限和维护成本，再用临时工作区试验指令注入、会话重开、中断和审批。不能确认外部执行停止时应把真实结果告诉用户；无法保持所需权限边界时不开放相应工具。用结果决定能力契约和最低接入范围。

## Q3 · 每轮要保留哪些执行依据？

**现象。** Turn 当前不能回答“这一轮请求了哪个模型、实际 Runtime 版本是什么、是否有单次批准”。Runtime 默认模型可变，原生服务还可能自行选模。人格的版本号也不足以还原每一次编辑。

**选项及建议。** 可以先维持精简记录；也可在双 Runtime 验证需要解释结果时，记录本轮请求的模型、可确认的实际模型与 Runtime 版本，对未知值明确留空。完整审批审计和人格修订历史会扩大数据量和隐私范围，建议由实际用途决定是否另行设计。请负责人明确最需要解释的历史问题，再确定字段及保留时间。

## 已经确定的边界

负责人已明确单机优先、Host 管持久身份和人格、Client 只访问 Host、Runtime 可替换、业务开发与架构审查分工，以及重要决策由负责人确认。V0.1 已采纳的具体实现见 [ADR 001](../adr/001-host-and-adapters.md)、[ADR 002](../adr/002-local-storage.md) 和 [ADR 003](../adr/003-private-codex-home.md)。记忆库选型、远程访问方案及上述问题的答案均待后续确认。
