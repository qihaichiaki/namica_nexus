# TASK-001 · Windows 双击启动、托盘与服务关停

业务基线 `6bebd16` · 负责人已确认范围 · 由 Developer 实现，Architect 验收。[ADR 004](../adr/004-windows-launch-and-shutdown.md)

## 用户体验

1. 完成一次项目安装和构建后，用户从资源管理器双击一个名称明确的 Namica Nexus 入口。启动后台 Host，确认就绪后在默认浏览器打开现有本地 Web Client，日常使用无需维持命令行窗口。再次启动可打开同一实例。README 告知入口位置、首次准备及启动失败时如何处理。
2. Windows 通知区域有一个可识别的 Namica Nexus 图标。右键提供“打开 Namica Nexus”和“退出 Namica Nexus”。关浏览器仅关闭 Client；托盘可以重新打开网页。“退出”表示停止该实例的 Host 并移除托盘。
3. 当前本机用户视为管理者。在现有 Web Client 的“设置 → 通用”中提供“终止服务”。明确提示“将中断正在执行的任务，并断开本地页面”，允许取消。确认后有可读的关停反馈，告知可再次双击启动。普通连接中断不可误报为已成功关停，失联后不能继续显示绿色“运行中”。从网页终止后托盘随实例退出。

## 实现边界

- [Host 入口](../../apps/host/src/main.ts)、[路由和关闭钩子](../../apps/host/src/app.ts)、[活动任务](../../apps/host/src/tasks.ts)和[设置页](../../apps/web/src/manage.tsx)是现有接入点。复用 `app.close()`、`Tasks.stop()` 和 SQLite 收尾路径。交给 Host 处理传输和终态，启动器只负责本地进程、托盘与打开浏览器。
- 关停请求先让调用方收到受理结果，再关闭监听；收尾期间停止接收新任务。重复点击、同时退出、托盘或 Host 已退出都应安全。保留用户消息、部分回复和已有原生线程映射，活动 Turn 记为 `interrupted`。跨来源的浏览器请求继续受既有回环、Host、Origin 和跨站校验约束，关停是显式写操作。
- 避免启动第二个相同实例。端口已被其他程序或另一份数据目录占用时，要告诉用户原因；不得按端口或进程名批量终止。兼容含空格、中文的路径，以及现有端口与数据目录配置。后台启动应有可见的失败反馈。
- 保留现有命令行启动和开发入口。本次范围为 Windows 本机默认浏览器、托盘和显式退出。登录自启、安装包、多用户权限、日志系统改造和独立桌面渲染层留待后续决定。具体托盘实现由 Developer 选择；若要引入新的桌面框架、运行时或改变部署前提，先反馈取舍。

## 验收与回报

| 场景 | 通过条件 |
| --- | --- |
| 冷启动、连点两次、关闭网页再打开 | 现有 Client 可用，同一实例只有一个 Host 与一个托盘；关闭网页后活动任务继续。 |
| 托盘右键退出 | 关闭正确 Host，托盘消失，原端口释放，可再次启动，已存历史可读。 |
| 设置中取消、确认终止服务 | 取消后可继续使用；确认后先收到受理反馈，再断开连接、移除托盘。意外断网或主机不可达时显示连接状态。 |
| 运行中含待审批任务时退出 | 重启后保留部分正文和映射，任务与未结束工具为中断状态，旧审批不可用；核对正常关停原因，区分启动时的崩溃补记。进行中的 Runtime 检测在有限时间内收尾，端口、数据库锁和子进程均释放。命令行启动的 Host 也能正常收尾。 |
| 其他程序占端口或其他实例在运行 | 只管理目标实例，给出可操作的提示，其他进程继续运行。 |

用临时数据目录、独立端口和合成输入验证，不操作用户正在使用的 Host。为关停与状态变化补回归，运行 `npm test`、`npm run build`。在 Windows 实测双击、托盘菜单与页面，分别报告已验证和未验证项。交回可获取的提交或 PR、启动入口、测试结果、实现取舍和限制。
