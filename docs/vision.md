# Namica Nexus

> Different agents. Persistent identities. One home.

Namica Nexus 是个人 PC 上的 AI Agent 宿主。一个身份可以经历多个任务、会话与 Runtime 升级，名称、人格版本与历史仍由使用者掌握。Codex 使用自己的认证与模型服务，本地优先指业务数据和控制面保存在用户的 PC 上。

平台的三个边界是 Agent、Host 和 Client。第三方 Agent 提供推理与工具，Host 管理持久身份和执行状态，Client 经 Host 帮助用户与这些身份交互。替换 Agent 或增加新 Client 时应保留这两个边界。

项目起点是让个人与 AI 人格长期相处。最终希望同一台个人 PC 上的多个身份能积累各自的经历，在被授权时使用本地项目、工具和软件工作，也能通过其他设备与人或彼此交流。身份延续体现在可追溯的经历、人格配置和行为约束上；更换模型后，实际表现仍可能变化。

## 长期设计约束

- **人格与上下文**　同一 Identity 可有多个 Session、选择或更换 Runtime。Host 持有人格的权威版本，按任务提供人格、相关记忆及当前状态。核心人格独立保存，普通会话压缩不能改写它。
- **记忆与证据**　保存原始经历，另行保存可重建的提取结果，关联来源并区分事实、推测和评价。支持追溯、更正和删除。工作记忆、近期经历、语义知识、技能、关系及自传式记忆按实际需求逐步验证。Host 可注入相关记忆，Agent 可按权限查询。私有记忆归属身份，共同经历和项目知识按明确规则共享。
- **主动性与协作**　从消息、定时或外部事件触发任务，普通程序能作出的选择由 Host 处理。模型调用受权限、执行轮数、时间、频率和预算约束。多个身份最终可以交流、委派、并行执行与互审，各自保有私有上下文。
- **多端与本地生产力**　Web、移动端、社交渠道和桌面形态都通过 Host 使用同一业务状态。文件操作、远程触发及数据发送遵循授权。模型可由云服务提供，第三方 Agent 继续承担推理和工具执行。
