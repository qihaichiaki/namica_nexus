# 路线图

V0.1 单机 MVP 已完成首次架构审查。代码基线、通过的测试和未验证范围见[工程基线](architect/current-state.md)。

## 后续方向（讨论稿）

| 版本 | 建议的验收场景，待负责人确认 |
| --- | --- |
| 0.2 | 同一 Identity 分别新建使用两种真实 Runtime 的会话。原会话保持绑定；两边的指令、工具、停止、审批和重启恢复均能说明支持范围，历史和失败状态可回读。先在仓外验证候选能力，再决定正式接入范围。 |
| 0.3 | 在新 Session 找回一条有来源的经历；可更正或删除派生记忆、核查原始证据，并验证私有记忆不会被另一身份检索。 |
| 0.4 | 授权的第二台设备能读取同一历史、观察任务并按权限操作；撤销授权后访问终止。 |
| 0.5 | 一个真实事件触发一次有权限、可取消的任务，重复事件与预算耗尽都有可观察的结果。 |
| 0.6 | 两个身份完成一次委派和互审，记录各自的任务、共享证据及私有信息边界。 |
| 1.0 | 以备份还原、升级迁移和长期运行演练验证用户可以持续使用自己的身份与历史。 |

版本号表示讨论顺序。正式立项取决于实际体验、上一阶段验收与负责人确认。第二种 Runtime、协议和记忆依赖均未选定；评估时记录实际版本、维护情况、许可证、Windows 兼容性与接入成本。[待讨论事项](architect/open-questions.md)
