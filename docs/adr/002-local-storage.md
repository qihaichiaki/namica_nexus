# ADR 002 · 身份与会话的本地存储

**状态**　V0.1 已采纳

**背景**　身份编辑、跨会话独立人格、失败后的部分回复都应可恢复。Runtime 内部线程不足以表达这些平台状态。

**方案**　比较逐文件 JSON、SQLite 和单独部署的数据库服务；比较直接复用第三方线程标识和保存平台映射。

**决定与理由**　使用 SQLite 事务和独立的平台标识，保存 Runtime 线程映射及会话创建时的人格版本。Host 和 Web 的业务恢复依赖同一份数据源。使用 Node.js 自带的 `node:sqlite` 减少 Windows 原生扩展安装步骤。

**影响**　发布需要支持 `DatabaseSync` 的 Node.js（本项目基线 22.18）。同步数据库操作适用于当前个人单机负载。长历史、高频写入及老版本数据库迁移须在后续变更时专门验证。

**2026-11-25 补充决定**　模型服务账号、模型版本和 Runtime 都可以更换。平台以同一 AI Identity 延续人格、历史记录和未来的长期记忆。原生会话恢复失败时保留原记录及其真实状态。未来可用 Host 持有的历史和记忆辅助新线程重建对话上下文。V0.1 的交付范围是保留历史、报告失败以及允许为同一身份新建会话。[五类概念的归属](../architecture.md#所有权与扩展边界)
